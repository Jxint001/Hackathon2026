## 1. 赛题与验收范围

### 1.1 赛题内容（场景 B）

赛题内容取自原题**问题 2**。给定一张计算图 DAG 与核心数 `N`（`N = 2,3,4,5`），参赛算法需要完成：

1. **切图**：为每个核内操作（除 `COPY_IN`、`COPY_OUT` 外的所有 `Op`）分配一个非负整数子图编号 `sgid`；
2. **子图调度**：将全部子图分配到 `N` 个同构 NPU 核心，并给出每个核心上的子图执行顺序。

评估规则（由官方 Python 评估器实现，选手无需实现）：

- 同一核心上的全部子图合并为**一个 Task**，同核子图之间直接复用 L1/UB 中的数据，不插入边界搬运；
- 跨核依赖由源核心插入 `COPY_OUT`、目标核心插入 `COPY_IN` 完成，目标 `COPY_IN` 需等待 **1000 cycles** 跨核同步延迟；
- 所有核心的 DDR 搬运共享固定总带宽 **60 bytes/cycle**；
- 核内调度必须能在固定 L1/UB 容量下展开（见 5.2）；
- 优化目标：**Makespan 最小**（主指标），**额外数据搬运量最小**（次指标）；
- **单核基准由组委会内部确定**，选手只需支持 `N = 2,3,4,5`。

### 1.2 交付边界

选手提交的是**方案生成程序**：读取计算图和核心数，输出多核切图与调度方案。Makespan、额外搬运量等指标由赛题官方 Python 评估器统一计算。

- 选手程序不得自行输出评分结果，也无需实现评估器；
- 方案必须能被官方评估器直接读取并通过合法性校验；
- 官方评估器与 5.2 的固定硬件参数由组委会统一提供，选手不得修改。

## 4. 程序调用

### 4.1 命令行

```text
npu_sched <graph.json> -n <N> -o <plan.json>
```

| 参数 | 取值 | 必需性 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `<graph.json>` | 路径 | 必需（唯一位置参数） | — | 输入计算图 |
| `-n, --cores` | 整数 `2~5` | 验收时必传 | `4` | 核心数 |
| `-o, --output` | 路径 | 验收时必传 | 见 4.2 | 方案输出文件 |
| `--version` | 无 | 可选 | — | 打印版本号并退出 0 |

- 同时支持 `--option value` 与 `--option=value`；
- 未知选项、非法值、缺少参数值以退出码 2 结束；
- 程序不接收配置文件参数，也不得读取 `config.txt`。

### 4.2 默认值与退出码

- `-o` 省略时，输出到 `<graph.json 所在目录>/<case>_multicore_res.json`；
- 输出目录不存在时应创建；创建失败以退出码 4 结束。

| 退出码 | 含义 |
| --- | --- |
| `0` | 成功，方案文件已完整写出 |
| `1` | 内部错误 |
| `2` | 命令行用法错误 |
| `3` | 输入数据错误 |
| `4` | 输出文件无法创建或写入 |
| `5` | 无法生成合法方案 |

### 4.3 运行约定

- 不得从 stdin 读取数据或等待交互；stdout 不被验收解析，错误信息写 stderr；
- 单次运行必须在 **90 秒**内主动结束并写出合法方案；
- 内存峰值 ≤ **16 GB**，线程数 ≤ **10**；
- 相同输入与相同命令行参数连续运行两次，输出方案文件必须完全一致。

### 4.4 示例

## 5. 输入与固定参数

### 5.1 计算图 JSON

UTF-8 编码的 JSON 对象，顶层包含 `tensors`、`ops`、`edges` 三个数组；节点 id 全局唯一且为非负整数。

| 数组 | 字段 | 含义 |
| --- | --- | --- |
| `tensors[]` | `id`、`pos`、`size` | 张量 id、位置（`DDR`/`L1`/`UB`）、字节数 |
| `ops[]` | `id`、`op`、`pipe`、`cycles` | 操作 id、类型、执行管道（`PIPE_M`/`PIPE_V`/`PIPE_MTE2`/`PIPE_MTE3`）、周期数 |
| `edges[]` | `source`、`target` | 边起点与终点，只允许 Tensor→Op 或 Op→Tensor |

- `COPY_IN` 表示 DDR→核内，`COPY_OUT` 表示核内→DDR；图输入/输出张量位于 DDR；
- 官方计算图保证为 DAG，并符合题目规定的格式与容量约束；
- 选手程序按官方格式读取即可，不要求兼容非法输入。

### 5.2 固定硬件参数

本赛题**不提供 `config.txt`**，以下参数为固定值（1 MiB = 1048576 bytes，1 KiB = 1024 bytes），必须直接写入程序常量：

| 参数 | 固定值 |
| --- | --- |
| L1 容量 | **1572864 bytes（1.5 MiB）** |
| UB 容量 | **131072 bytes（128 KiB）** |
| DDR 总带宽 | **60 bytes/cycle** |
| 跨核等待 | **1000 cycles** |

不得通过命令行、环境变量或任何文件覆盖上述参数。

## 6. 输出

### 6.1 方案 JSON

顶层必须且只能包含两个字段：

```json
{
  "node_to_subgraph": {
    "<核内操作 id>": "<非负整数 sgid>"
  },
  "core_schedules": [
    ["<核心 0 的 sgid 执行顺序>"],
    ["<核心 1 的 sgid 执行顺序>"]
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `node_to_subgraph` | 核内操作 id（十进制字符串）到 sgid 的映射，必须恰好覆盖全部非 COPY 操作 |
| `core_schedules` | 外层长度为 `N`；内层为该核的 sgid 执行顺序，可为空数组 |

### 6.2 合法性约束

方案必须同时满足：

1. 顶层恰好包含 `node_to_subgraph` 和 `core_schedules` 两个字段；
2. `node_to_subgraph` 恰好覆盖全部非 COPY 操作，不包含 COPY 操作或不存在的 id；
3. 键为规范十进制字符串（无前导零、无正负号、无空格），值为非负整数 sgid；
4. `core_schedules` 外层长度等于 `N`，展平后每个 sgid 恰好出现一次；
5. 由跨子图依赖构成的子图依赖图无环；
6. 同一核心上的子图顺序不得违反依赖关系；
7. 方案必须能被官方场景 B 评估器完整执行（不得出现容量失败、死锁等错误）。

无法生成合法方案时以退出码 5 结束，不得写出非法方案文件。

## 7. 合法性与评分

### 7.1 验收流程

1. 解压到 ASCII 路径，检查第三方库与禁止内容；
2. Linux（GCC）与 Windows（MSVC）各构建一次；
3. 对每个公开/隐藏用例、每个 `N ∈ {2,3,4,5}`，按 4.1 调用程序；
4. 用官方场景 B 评估器评估方案，记录 Makespan 与额外搬运量；
5. 汇总各核数下的加速比，抽样验证确定性。

### 7.2 合法性判定

| 现象 | 判定 |
| --- | --- |
| 任一平台构建失败 | 提交不合格 |
| 退出码非 0、超时、崩溃 | 该用例判 0 |
| 方案非法或评估器报错 | 该用例判 0 |
| 任一用例在任一核数下无效 | 合法性门槛不通过 |
| 输出不确定 | 要求修复或判定不合格 |
| 硬编码、读取答案、针对用例特判 | 取消参赛资格 |

### 7.3 指标与评分

官方评估器输出 Makespan 与额外搬运量。单核基准 `T_single(case)` 由组委会内部确定；对于 `N` 核：

```text
S(case, N) = T_single(case) / T_N(case)
```

评分建议口径（最终以组委会评分细则为准）：

- **主分**：`N = 2..5` 的平均加速比，即

  ```text
  Score = (1/4) * Σ_{N=2..5} (1/|C|) * Σ_{case∈C} S(case, N)
  ```

- **并列排序**：主分相同时，比较平均额外搬运量占比 `added_copy_bytes / max(1, original_graph_copy_bytes)`，越低越优；
- 运行时间不计入主分，但超过 90 秒即判该用例 0 分。

### 7.4 防作弊

1. 不得硬编码用例文件名、id 集合、哈希值或预生成方案；
2. 不得根据文件名、文件大小等做用例特判；算法必须由输入图和核心数驱动；
3. 不得修改官方评估器、测试数据或固定硬件参数；隐藏用例会重命名并扰动输入。

## 附录 B 常见问题

**Q1：能否使用 `nlohmann/json`？**
可以，按 3.3 放入 `third_party/` 并随包提交完整源码；禁止复杂/重型库。

**Q2：核心数范围？**
验收只使用 `N = 2,3,4,5`；传入其它值时程序应返回退出码 2，不得崩溃。

**Q3：是否还需要读取 `config.txt`？**
不需要。硬件参数固定为 5.2 的值，直接写在程序常量中。

**Q4：能否使用多线程？**
可以，使用标准库 `std::thread`，线程数 ≤ 10，结果必须确定。

**Q5：方案文件能否包含 Makespan 等额外字段？**
不能。顶层只能包含 `node_to_subgraph` 和 `core_schedules`。

**Q6：90 秒内还没找到好方案怎么办？**
必须主动结束并写出当前已知的最优合法方案；合法但一般的方案远优于超时无输出。
